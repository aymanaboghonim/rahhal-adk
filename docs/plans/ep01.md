# ep01 plan: Tools on a free key (`ep01-tools`)

Masar: Foundation lab + session 1 "Empowering AI Agents with Tools" (2026-11-18). Status: **approved, in progress.**

"PoC" below means the author's private trial project (a proof of concept, not published) where every pattern
was first tested on a free key; this plan says what is ported from it and what is simplified.

## Goal
In one episode a learner can open a Codespace (or a local setup), add a free AI Studio key, run Rahhal in
`adk run` and `adk web`, watch it call three local Python tools, see a fiqh question answered by a callback
without a model request, and check the agent with golden cases.

## Decisions (from the planning session)
| Topic | Decision |
|-------|----------|
| Environment | Codespaces first (`.devcontainer/`), local second; the same `uv run …` commands everywhere |
| Key | Codespaces recommended secret `GOOGLE_API_KEY`; fallback `.env` at the repo root |
| Self-check | `uv run python scripts/check.py ep01` (no Makefile) |
| Evaluation | `pytest` offline + `pytest -m live` (ADK `InMemoryRunner`); `adk eval` comes in `bonus-evals` |
| Dependencies | `google-adk==2.14.0`, `salat[full]==1.1.1`, `hijridate==2.3.0`; dev group: `pytest` |
| Python | `>=3.12`; devcontainer image 3.14; CI on 3.12 and 3.14 |
| License | Code Apache-2.0; lessons and docs text CC BY 4.0 |

## How evaluation runs in ep01
1. **`uv run pytest -q`** (offline, CI, no key): tools, guardrail, data determinism, and the two filter-layer golden
   cases (the callback runs without a model).
2. **`uv run pytest -m live -v`** (free key, about 20 requests): each case runs through ADK's `InMemoryRunner`; the
   test checks the tool calls, argument subsets and reply text. Observe-only cases print their result but don't
   fail. Optional `GOLDEN_RUNS=3` repeats each case (a weak model varies). Results are noted here with the date
   and model before tagging.
3. **`adk eval` / Evals tab:** not in ep01. One lesson line says they come in `bonus-evals` (heavy `[eval]` extra,
   custom-metric registration, Vertex-only metrics need billing).

## `scripts/check.py ep01`
Prints ✅/❌ per check with a one-line fix. **Never prints a secret value**, only whether it is set and where it
comes from. Exit code 1 if any check fails.

| Check | Fix message (gist) |
|-------|--------------------|
| Python ≥ 3.12 and `google-adk` 2.14.0 importable | `uv sync` |
| Key source. In Codespaces (`CODESPACES=true`): `GOOGLE_API_KEY` from the secret **or** the root `.env`. Locally: the root `.env`. Says which one wins (shell variables beat `.env`) | Codespaces: github.com/settings/codespaces → New secret `GOOGLE_API_KEY` → allow this repository → restart the codespace; or `cp .env.example .env` and add the key |
| `GOOGLE_GENAI_USE_ENTERPRISE=0` (devcontainer env or `.env`) | add it to `.env` |
| No `rahhal/.env` (ADK stops at the first `.env`, so it would shadow the root one) | delete it or merge it into the root `.env` |
| Locally: no `GOOGLE_API_KEY`, `GEMINI_API_KEY` or `RAHHAL_MODEL` exported in the shell. Everywhere: warn if `GEMINI_API_KEY` is set | `unset NAME` (bash) / `Remove-Item Env:NAME` (PowerShell); restart VS Code if it comes back |
| Data files present and identical to a fresh generation | `uv run python scripts/generate_data.py` |
| Tool smoke: 40000 EGP → 3000 SAR; elderly-friendly hotels in Makkah > 0; today's prayer times for Makkah | `uv sync`; regenerate data |
| `pytest -q` passes | read the failing test |
| Secret scan: no `AIza[0-9A-Za-z_-]{35}` in tracked or untracked-not-ignored files; `.env` is git-ignored | remove it and **rotate the key** in AI Studio |

   - Setup installs everything and runs the self-check. Then `uv run adk web` and open port 8000 from the

2. **Option B: your machine (Linux, WSL, Windows)**
   install uv → `uv sync` → `cp .env.example .env` and add your key → `uv run python scripts/check.py ep01` →

3. **Get a free key:** Google AI Studio → create a **new project without billing** → create an API key → check the

   - Runs locally (or in your codespace): the three tools, the data, prayer-time calculation, the fiqh filter, the tests.

   - Privacy: on the free tier Google may use prompts to improve its products, so all data here is fictional.
   - No Google Search: no free search-grounding model works for a new key (tested 2026-11-23).
   - Vertex-based evaluation metrics need billing; we don't use them.

## How concepts are taught (concept cards)
Each concept appears just before the step that uses it, as a short card. The card's formula is also the
`# 📘 Concept:` comment in the code, so the screen and the lesson match. Card shape:
**formula** → **in Rahhal** (the lines) → **see it** (what to point at) → **🧪 do it** (one message) → (optional) why it
matters on the free tier.

| # | Concept | Formula / intuition | Shown with |
|---|---------|---------------------|------------|
| 1 | Agent | `Agent = Model + Instruction + Tools`: the brain, the job description, the hands | `root_agent = Agent(…)`; the app list in `adk web` |
| 2 | Tool | `Tool = Python function + docstring`: the model reads the name, docstring and type hints, never the body | the `convert_currency` docstring; Events tab `function_call {amount: 40000, from_currency: "EGP", …}` |
| 3 | Agent loop | `1 message ≈ 2 requests`: the model decides → the tool runs locally → the model writes the reply | Events tab: call → response → text; links to 15 requests per minute |
| 4 | Instruction rules | rules shape behaviour; a weak model follows them imperfectly | rule 7 (budget cap) → `budget_plan_full` shows 375 instead of 214 |
| 5 | Callback | `Callback = a hook ADK calls at a fixed moment`; `before_agent_callback` can answer instead of the model | a fiqh question → the referral with 0 requests (nothing in the terminal) |
| 6 | Golden case | `golden case = input + expected behaviour`: a unit test for the agent | one YAML case → its `pytest -m live` line |
| (light) | Session / Event | each chat is a session, each step an event | only named; deepened in ep02 |

A Mermaid diagram of the loop (user → agent → tool → agent → reply) sits outside the RTL block; its rendering is
part of the RTL Preview test.

Challenges at the end (no coding): switch `RAHHAL_MODEL` to `gemini-3.1-flash-lite` and re-run
`pytest -m live` (which cases change?); ask a fiqh question in new words (filter or instruction?).

## Risks and open questions
- ep01 is long for one video (three tools, guardrail, retries, evals): the lesson is chaptered; the guardrail
  chapter can become a part 2 if needed.
- Flash-Lite varies run to run: one live run can mislead (`GOLDEN_RUNS=3`).
- Recording: explain the Codespaces free quota from GitHub's docs, not from a personal billing page.
- Models can return 503 at peak times: retries and the Arabic "busy" reply cover it; record off-peak.
- The devcontainer uses Python 3.14 while the codelabs use 3.12: CI covers both.
- `hijri-converter` is deprecated; pinned versions keep it working; replacing `salat` is not planned.
